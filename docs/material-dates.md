# 原材料日期（不是入库时间）

prepared 的来源 JSON 支持 document_date（封面/材料日期）、published_at（原文发布日期）、effective_at（业务生效日期）。只能依据原文，不能用下载、采集、入库、文件属性时间代替。

日期保留实际精度：YYYY、YYYY-MM、YYYY-MM-DD；原文有时分也可用 ISO 时间。不知道日期就省略字段，填写 date_status=unknown、date_note 说明检查过哪里；知道材料/发布日期填 known，date_evidence 记录各字段对应的原文位置和日期原话。生效时间独立记录，不作为资料年龄。

网页优先显示发布日期，其次材料日期；来源详情保留全部字段。日期范围使用精度区间相交匹配：只有“2025”时不会伪造某一天。支持未知日期、超过一年、起止日期筛选与原材料日期排序。超过一年仅提示复核，不自动删除、不判失效；新旧不替代事实判断。

未检查日期、格式无效、缺日期依据会在 prepared 回执提示；未知但已说明检查范围可以保存通过。历史回执的日期检查会依据最新日期元数据动态呈现，其他原有检查保留。archive/compile 尚无这些结构化入参，网页显示日期未记录，不能假称已核验。

## 历史补录

`python _service/scripts/backfill_material_dates.py` 默认只生成本地报告；检查报告后加 `--apply` 才更新。只处理已有明确封面备注、未知备注，以及单篇原始网页 ZIP 中 main/h1 前的明确文章日期。不会扫描正文年份、文件名、采集时间或联网；有歧义不猜。

更新前备份 SQLite 到 `_local/backups/`，记录逐条旧/新元数据。写入有并发版本校验，任何条目已变化则整批回滚。只补来源元数据，不改正文、知识稿版本和业务裁决；不要在公共仓库提交备份及报告。脚本未覆盖所有格式，未补齐的材料仍须客户端按原文检查。

隔离回归：`python _service/scripts/test_material_dates.py`；不会调用模型或触碰存量库。
