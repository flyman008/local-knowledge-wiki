# 维护、备份恢复与排错

## 文件归属

- `_service/`：实现代码；`examples/`、`docs/`：公开演示和教程。
- `content/`：真实内容与各层材料。
- `_local/`：数据库、私有配置、日志等运行态数据。

备份 content 和 _local 的完整配套副本，不能只复制 wiki。自定义配置引用外部目录时也必须备份对应目录。备份可能含密钥和内部资料，存到私有受控位置，不上传公共仓库。

## 最简单可靠的备份与恢复

1. 暂停所有客户端提交和定时任务，在服务终端按 Ctrl+C，确认本实例退出。
2. 将 content/、_local/ 完整复制到带日期的独立备份目录，并记录当前代码 commit。停服复制可避免数据库与文件版本不一致；不要在运行时只拷 knowledge.db 而忽略 WAL。
3. 在独立测试目录恢复代码版本和两份数据目录，检查配置路径指向测试副本，不能仍引用生产目录。
4. 测试副本用其他端口启动网页，只用浏览器/API验证，现有 CLI 固定访问 8765，不用于该副本。
5. 验证文章数量、代表性正文、原件、来源、历史版本和待确认记录。通过后才考虑正式恢复。

不要以删除旧目录作为升级步骤。正式恢复前先保存当前状态，以便回退；回退代码时应配套还原备份数据库和文件，而不是只降级 Python 文件。

## 升级

先备份并记录 commit，再确认 git status 没有未保护的本地改动，然后拉取更新、按 requirements 安装依赖、重启并验证。依赖目前是最低版本约束而非完整锁定，不能保证未来安装解析出完全相同环境。发布仓库只是实现快照，不会自动同步任何正在使用的知识库。

## 常见问题

| 表现 | 处理 |
|---|---|
| 连接失败 / 8765 未运行 | 按 setup 手动启动，查看服务终端，不要反复提交 |
| 启动要求模型 token | 检查是否误用了 app.py；无模型模式使用文档中的 uvicorn 命令 |
| 端口占用 | 核对监听进程和库路径；不要停止不明服务或把示例投进别人的库 |
| CLI 退出码 2 | 可能参数错误或等待超时；若已有回执先查状态，不能直接重投 |
| CLI 退出码 3 | 可能缺层、解析不完整或检查提醒；读取回执详情，已保存部分不要重复提交 |
| 搜得到但正文缺失 | 检查是否二进制原样归档而没有 prepared 解析稿 |
| 新版本待确认 | 查看冲突双方和适用范围，由用户确认，不自动以最新稿覆盖 |
| 改代码后无变化 | 核对运行进程和实际目录；仓库副本不等于在线实例 |

退出码 0 也不代表所有业务事实已经人工确认；持续查看待确认项。保留 receipt_id、源文件指纹和进度记录，避免在不同客户端重复入库。

## 安全边界

只绑定 127.0.0.1，不开放路由端口，不用公网隧道直接暴露。没有账号鉴权和多租户隔离；网页只读不等于 HTTP API 无写入能力。其他本机进程仍可能访问接口。服务器部署需要另行建设访问控制、TLS、备份和安全验证。
