# 媒体保存策略

客户端负责转写、逐段画面核验和来源可回访声明；服务不调用模型，只检查材料、引用、哈希与状态。完整命令及清单格式见 [Skill 媒体说明](../_service/skills/knowledge-intake/references/media.md)。

- 图片按内容去重；像素尺寸不变、解码像素一致、关键元数据核对通过且体积至少减少 5% 才采用无损 WebP。
- 视频和音频保留解析文字、时间定位、来源；视频与动图额外要求关键帧与画面说明。不能把第一帧当作完整动图。
- 先 prepared 保存三层，再提交媒体清单生成保留包。ready 不会删除原件；只有明确 stage 才开始 7 天可取消等待期。
- 到期重新检查解析完整性、待确认事项、解析稿与保留对象哈希、共享原件的所有回执；任何条件不满足则暂缓。
- 唯一本地来源、未完整解析、未核验的素材不能清理。历史材料不会自动迁移。
- PDF、Office 文档和嵌套压缩包不拆除内部媒体。当前支持独立媒体或平铺/目录式 ZIP 采集包。

服务须以单进程运行（不要使用多 worker）。启动后独立维护线程每小时检查已 stage 的计划；停机期间不清理，重启后继续检查。端口仅供本地使用。

精简包不是原件；视频删除后只能回访来源，原链接可能失效。7 天内 cancel 保留原件，purged 后不能承诺恢复。取消计划的共享对象暂不自动回收，优先保护引用安全。页面展示的是原始媒体字节与保留对象字节，不等同实际压缩包磁盘节省。

验证脚本：`py -3.12 _service/scripts/test_media_retention.py`。使用临时库与合成素材，覆盖存储和清理机制，不证明实际转写或视觉理解质量，不调用付费模型。
