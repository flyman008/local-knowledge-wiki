# 工作原理与边界

这是本地优先的知识保存与阅读工具，不是自动保证事实正确的系统，也不是托管云知识库。

## 一份资料怎样成为知识

1. 用户把材料交给具有读文档、读图能力的客户端。
2. 客户端保留原件 raw，制作忠实解析稿 extract，再制作知识稿 wiki。英文原件与解析稿保留英文，知识稿可写中文。
3. 客户端依据 Skill 调用 intake.py，通过本机 HTTP 接口提交三份内容和来源信息。
4. 服务保存文件、登记回执与版本、建立检索、列出需要关注的问题。
5. 用户在网页阅读、搜索、回查来源；冲突通过确认接口处理，不由收件动作自动裁决。

PDF 混排图片、PPT 图表、Excel 工作表和公式不能因已经提取文字就算看完。解析不了时应声明缺失，不伪装成完整成果。

## 谁负责什么

| 部件 | 责任 | 不负责 |
|---|---|---|
| 客户端 / Agent | 理解用户意图、读图文、整理和标记缺失 | 不直接改知识库数据库 |
| Skill | 操作约定、确认边界 | 不是权限隔离或事实验证器 |
| intake.py | 上传、查询回执和状态 | 不决定业务事实谁对谁错 |
| FastAPI 服务 | 保存、索引、版本、确认记录 | prepared 不重新调用模型整理 |
| SQLite + 文件目录 | 索引、状态、原件、解析稿与成果 | 不能只备份其中一项 |
| 本地网页 | 浏览、检索、回查 | 不是公网多用户管理后台 |

默认教程不开启后台模型。只有用户明确选择 compile/后台问答时，才需要额外模型服务与费用；客户端本身仍可能消耗其账户额度。

## 分类和质量

只有一个存储 ID：library。weimob/external 是原项目的资料范围，AI、SaaS 是可同时存在的标签。范围按材料讲谁判断，不按发布者判断。其他组织复用时可先使用 external，不要将范围改成另一个库；修改分类枚举需要同步客户端与服务校验，不是只改配置文字。

保存完成、客户端声明解析完整、自动检查通过、内容经过人工核验，是四个不同状态。版本号表示知识稿修订次数，不意味着产品版本更新或来源更权威。获取时间也不等于事实生效时间。

来源优先级取决于问题：技术实现参考对应代码依据，规划参考 PRD，价格参考生效商业政策，客户承诺参考合同。范围、版本不一致时保留双方，不做无条件覆盖。轻量检查无法发现所有语义冲突；必须结合关键事实抽查。

## 尚未交付的通用能力

未包含通用公众号/微盘采集器、自建 MCP Server、一键三端安装器、登录鉴权、多租户、云端部署和自动事实核验。原项目的内部自动化不等于仓库已提供这些能力。
